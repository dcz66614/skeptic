## OpenAI Agents SDK 0.24.0

`Agent.instructions` 默认是 `None`。该字段的文档把它称为系统提示词。`prompt` 也默认是 `None`。`instructions` 为 `None` 时，`get_system_prompt` 返回 `None`。默认智能体没有关于工具失败的系统提示词。出处：[`agent.py` 的 instructions](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/agent.py#L332-L346)、[`get_system_prompt`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/agent.py#L1129-L1158)。

`tool_use_behavior` 默认是 `"run_llm_again"`：工具执行后，结果交回给 LLM。函数工具抛出的异常由 `_FailureHandlingFunctionToolInvoker` 接住。默认格式化函数返回固定字符串 `An error occurred while running the tool. Please try again.` 它的文档写明，这个格式化函数不把异常本身交给模型。格式化函数返回 `None` 时，异常继续抛出。这段捕获外面没有单独的重试计数。`Runner.run` 的 `max_turns` 默认取 `DEFAULT_MAX_TURNS`，值为 10。超过该上限时，除非错误处理器接住，否则抛出 `MaxTurnsExceeded`。出处：[`tool_use_behavior`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/agent.py#L396-L404)、[`调用包装`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/tool.py#L697-L711)、[`default_tool_error_function`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/tool.py#L1997-L2002)、[`DEFAULT_MAX_TURNS`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/run_config.py#L45)、[`run 签名与 MaxTurnsExceeded`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/run.py#L287-L309)、[`轮次检查`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/run.py#L1598-L1606)。

MCP 工具结果带 `isError` 时，工具输出保留结果内容。只有服务器要求使用结构化内容，且结果不是错误时，才改用 `structuredContent`。调用 MCP 工具期间抛出的异常会重新进入同一套函数工具失败处理。该处注释写明，默认处理器给出结构化错误结果；`failure_error_function=None` 时错误继续传播。出处：[`invoke_mcp_tool`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/mcp/util.py#L750-L799)。

`output_type` 默认是 `None`。字段文档写明，未提供类型时输出为 `str`。`output_type` 为 `None` 或 `str` 时，`get_output_schema` 返回 `None`；其他类型会构造 `AgentOutputSchema`。调用方传入类型时，`AgentOutputSchema` 的 `strict_json_schema` 默认为 `True`。`output_guardrails` 默认为空列表。出处：[`output_type 与 guardrails`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/agent.py#L373-L390)、[`get_output_schema`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/run_internal/turn_preparation.py#L124-L131)、[`AgentOutputSchema`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/agent_output.py#L85-L98)。

## LangGraph 1.2.20 与 LangChain 1.4.9

本版 `create_react_agent` 已弃用。文档写明该函数迁到 `langchain.agents.create_agent`。它的 `prompt` 参数默认是 `None`。调用方传入工具列表而不是现成的 `ToolNode` 时，函数构造 `ToolNode(...)`，并且不传 `handle_tool_errors`。出处：[`弃用说明与 prompt`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py#L274-L292)、[`ToolNode 构造`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py#L554-L560)。

`langchain.agents.create_agent` 的 `system_prompt` 默认是 `None`，`response_format` 默认是 `None`。文档把两者都写成可选项。它构造 `ToolNode` 时只传入工具包装，同样不传 `handle_tool_errors`。出处：[`签名`](https://github.com/langchain-ai/langchain/blob/d1d95b79213b0212613ae1aa4fad38bea6f1dccf/libs/langchain_v1/langchain/agents/factory.py#L892-L899)、[`文档`](https://github.com/langchain-ai/langchain/blob/d1d95b79213b0212613ae1aa4fad38bea6f1dccf/libs/langchain_v1/langchain/agents/factory.py#L941-L959)、[`ToolNode 构造`](https://github.com/langchain-ai/langchain/blob/d1d95b79213b0212613ae1aa4fad38bea6f1dccf/libs/langchain_v1/langchain/agents/factory.py#L1140-L1147)。

`ToolNode.handle_tool_errors` 默认是 `_default_handle_tool_errors`。异常属于 `ToolInvocationError` 时，该函数返回 `e.message`；其他异常重新抛出。`ToolInvocationError.message` 来自 `TOOL_INVOCATION_ERROR_TEMPLATE`，内容包含工具名、参数、错误文本，以及句子 `Please fix the error and try again.` 被处理的错误变成 `status="error"` 的 `ToolMessage`。`GraphBubbleUp` 和无效的 resume 值在这条分支之前重新抛出。出处：[`模板`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L116-L129)、[`ToolInvocationError.message`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L381-L388)、[`默认处理器`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L391-L399)、[`参数默认值`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L751-L761)、[`处理或重新抛出`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L995-L1029)。

默认可调用对象的注解参数类型是 `Exception`，因此 `_infer_handled_types` 把 `Exception` 当作可处理类型，然后再调用该函数。函数自身会把不是 `ToolInvocationError` 的异常重新抛出。出处：[`_infer_handled_types`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L500-L502)。

`create_agent` 或 `create_react_agent` 的 `response_format` 被设置之后，才有结构化输出。两个参数的默认值都是 `None`，出处见上文。

## CrewAI 1.15.39

`Agent.use_system_prompt` 默认是 `True`。`system_template`、`prompt_template`、`response_template` 默认是 `None`，因此使用英文 i18n 片段。`Prompts.task_execution` 从 `role_playing` 片段开始。智能体有工具且未使用原生工具调用时，再附上 `tools` 片段。原生工具调用把用户轮次选成 `native_task` 片段。是否启用原生调用，由构建提示词时的 `_supports_native_tool_calling(raw_tools)` 决定。出处：[`提示词字段`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agent/core.py#L285-L311)、[`提示词组装`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/utilities/prompts.py#L93-L131)、[`原生调用选择`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agent/core.py#L1309-L1315)。

`role_playing` 片段是 `You are {role}. {backstory}\nYour personal goal is: {goal}`。`tools` 片段描述 Thought、Action、Action Input 和 Observation。`native_task` 片段是 `Current Task: {input}`。这三段都没有说明工具抛出异常时怎么处理。失败文案在 `errors` 下，其中包括 `tool_usage_exception`，稍后才被格式化成错误观察。出处：[`en.json` 片段](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/translations/en.json#L11-L16)、[`errors.tool_usage_exception`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/translations/en.json#L50-L55)。

文本动作路径上，`ToolUsage` 把 `_max_parsing_attempts` 设为 3；函数调用模型属于 `OPENAI_BIGGER_MODELS` 时设为 2。工具异常会增加尝试次数。次数未用完时再次调用 `ause`。超过上限后，返回包含 `errors.tool_usage_exception` 和 `format` 片段的 `ToolUsageError` 字符串。出处：[`尝试上限`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/tools/tool_usage.py#L109-L134)、[`异常分支`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/tools/tool_usage.py#L451-L499)。

原生工具调用路径上，异常被接住，工具消息内容设为 `Error executing tool: {e}`。该函数不会再次调用工具。随后 `handle_tool_failure` 应用解析出的策略。智能体和任务上的 `tool_failure_policy` 默认都是 `None`。`None` 表示继承，解析器最终落到 `ToolFailurePolicy.WARN`。`WARN` 记录失败、发出 `ToolFailureDetectedEvent` 并返回。`RAISE` 抛出 `ToolExecutionFailedError`。出处：[`原生路径的 except`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/utilities/agent_utils.py#L1685-L1704)、[`原生工具消息`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/utilities/agent_utils.py#L1752-L1769)、[`智能体策略字段`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agents/agent_builder/base_agent.py#L288-L296)、[`解析器`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/tools/tool_failure.py#L180-L211)、[`WARN 与 RAISE`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/tools/tool_failure.py#L60-L71)、[`handle_tool_failure`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/tools/tool_failure.py#L345-L387)。

`Agent.max_retry_limit` 默认是 2。`_check_execution_error` 会重新抛出透传异常，以及模块名以 `litellm` 开头的异常。其他异常增加 `_times_executed`，计数超过 `max_retry_limit` 后重新抛出。未超过时，`_handle_execution_error` 再次调用 `execute_task`。这层重试包住的是任务执行。出处：[`max_retry_limit`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agent/core.py#L325-L328)、[`_check_execution_error`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agent/core.py#L908-L934)、[`_handle_execution_error`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agent/core.py#L936-L955)。

`Task.output_json`、`output_pydantic`、`response_model` 默认是 `None`。`guardrail` 和 `guardrails` 默认是 `None`。`guardrail_max_retries` 默认是 3，在设置了 guardrail 时生效。`errors.validation_error` 片段是 guardrail 失败后使用的文本。出处：[`输出字段`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/task.py#L185-L214)、[`guardrail`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/task.py#L262-L290)、[`validation_error`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/translations/en.json#L55)。

设置了 `output_schema` 时，如果智能体不在任务模式，并且没有函数工具或模型报告 `output_schema_and_tools`，基本请求处理器会调用 `llm_request.set_output_schema`。存在函数工具且模型没有报告该能力时，输出 schema 处理器会附上 `set_model_response` 工具，并附上一条要求最终响应使用它的说明。把最终文本写入会话状态时，只有 `output_schema` 和 `output_key` 都设置了才会调用 `validate_schema`。对 `BaseModel` schema，`validate_schema` 使用 `model_validate_json`。默认 `output_schema` 是 `None`，因此默认智能体不进入这些分支。出处：[`set_output_schema`](https://github.com/google/adk-python/blob/93814c3475916bf873236f4e30f6915b4b9c8698/src/google/adk/flows/llm_flows/basic.py#L130-L143)、[`set_model_response`](https://github.com/google/adk-python/blob/93814c3475916bf873236f4e30f6915b4b9c8698/src/google/adk/flows/llm_flows/prompt/_schema.py#L67-L88)、[`状态校验`](https://github.com/google/adk-python/blob/93814c3475916bf873236f4e30f6915b4b9c8698/src/google/adk/agents/llm_agent.py#L1111-L1145)、[`validate_schema`](https://github.com/google/adk-python/blob/93814c3475916bf873236f4e30f6915b4b9c8698/src/google/adk/utils/_schema_utils.py#L239-L260)。

`KernelFunction.invoke` 记录函数异常后重新抛出。`Kernel.invoke_function_call` 在 `_inner_auto_function_invoke_handler` 里接住该异常，把函数结果设为 `An error occurred while invoking the function {name}: {exc}`。随后把 `FunctionResultContent` 消息写入聊天历史。函数不存在、JSON 参数畸形、参数集合不对，也会在函数体运行前写成函数结果。参数无法解析成声明类型时，`_parse_parameter` 抛出 `FunctionExecutionException`；它是 `Exception`，因此走同一个处理器。出处：[`invoke 重新抛出`](https://github.com/microsoft/semantic-kernel/blob/d08a482fab9c6980fa50de5eee79895ba702069d/python/semantic_kernel/functions/kernel_function.py#L274-L294)、[`处理器`](https://github.com/microsoft/semantic-kernel/blob/d08a482fab9c6980fa50de5eee79895ba702069d/python/semantic_kernel/kernel.py#L466-L489)、[`写入历史`](https://github.com/microsoft/semantic-kernel/blob/d08a482fab9c6980fa50de5eee79895ba702069d/python/semantic_kernel/kernel.py#L455-L464)、[`参数错误`](https://github.com/microsoft/semantic-kernel/blob/d08a482fab9c6980fa50de5eee79895ba702069d/python/semantic_kernel/kernel.py#L359-L425)、[`参数解析`](https://github.com/microsoft/semantic-kernel/blob/d08a482fab9c6980fa50de5eee79895ba702069d/python/semantic_kernel/functions/kernel_function_from_method.py#L124-L157)。
