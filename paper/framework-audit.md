## OpenAI Agents SDK 0.24.0

`Agent.instructions` defaults to `None`. The field docstring calls that value the system prompt. `prompt` also defaults to `None`. `get_system_prompt` returns `None` when `instructions` is `None`. The default agent therefore has no system-prompt text about a failed tool. Sources: [`agent.py` instructions and prompt](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/agent.py#L332-L352), [`get_system_prompt`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/agent.py#L1129-L1158).

`tool_use_behavior` defaults to `"run_llm_again"`: tools run, and the LLM receives the results. A function-tool exception is caught by `_FailureHandlingFunctionToolInvoker`. The default formatter returns the fixed string `An error occurred while running the tool. Please try again.` Its docstring says this formatter does not expose the exception to the model. If the formatter returns `None`, the exception is re-raised. There is no separate retry counter around that catch. `Runner.run` defaults `max_turns` to `DEFAULT_MAX_TURNS`, which is 10. Exceeding that limit raises `MaxTurnsExceeded` unless an error handler takes it. Sources: [`tool_use_behavior`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/agent.py#L396-L404), [`invoker`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/tool.py#L697-L711), [`default_tool_error_function`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/tool.py#L1997-L2002), [`DEFAULT_MAX_TURNS`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/run_config.py#L45), [`run signature and MaxTurnsExceeded`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/run.py#L287-L309), [`turn check`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/run.py#L1598-L1606).

An MCP tool result flagged `isError` keeps its content as the tool output. `structuredContent` is used only when the server asked for it and the result is not an error. An exception raised while calling the MCP tool is re-raised into the same function-tool failure pipeline. The comment at that site says the default handler surfaces a structured error result, and `failure_error_function=None` lets the error propagate. Sources: [`invoke_mcp_tool`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/mcp/util.py#L750-L799).

`output_type` defaults to `None`. The field docstring says the output is `str` when the type is omitted. `get_output_schema` returns `None` when `output_type` is `None` or `str`, and builds an `AgentOutputSchema` otherwise. `AgentOutputSchema` defaults `strict_json_schema` to `True` for a caller-supplied type. `output_guardrails` defaults to an empty list. Sources: [`output_type` and guardrails](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/agent.py#L373-L390), [`get_output_schema`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/run_internal/turn_preparation.py#L124-L131), [`AgentOutputSchema`](https://github.com/openai/openai-agents-python/blob/17d994bd3045dae71acda676a4ef4762ed8ecd94/src/agents/agent_output.py#L85-L98).

## LangGraph 1.2.20 and LangChain 1.4.9

`create_react_agent` is deprecated in this release. Its docstring says the function moved to `langchain.agents.create_agent`. Its `prompt` argument defaults to `None`. When the caller passes a tool list rather than an existing `ToolNode`, the function constructs `ToolNode(...)` and does not pass `handle_tool_errors`. Sources: [`deprecation and prompt`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py#L274-L292), [`ToolNode construction`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py#L554-L560).

`langchain.agents.create_agent` defaults `system_prompt` to `None` and `response_format` to `None`. The docstring describes both as optional. Its `ToolNode` is constructed with tool wrappers only, again without `handle_tool_errors`. Sources: [`signature`](https://github.com/langchain-ai/langchain/blob/d1d95b79213b0212613ae1aa4fad38bea6f1dccf/libs/langchain_v1/langchain/agents/factory.py#L892-L899), [`docstring`](https://github.com/langchain-ai/langchain/blob/d1d95b79213b0212613ae1aa4fad38bea6f1dccf/libs/langchain_v1/langchain/agents/factory.py#L941-L959), [`ToolNode construction`](https://github.com/langchain-ai/langchain/blob/d1d95b79213b0212613ae1aa4fad38bea6f1dccf/libs/langchain_v1/langchain/agents/factory.py#L1140-L1147).

`ToolNode.handle_tool_errors` defaults to `_default_handle_tool_errors`. That function returns `e.message` when the exception is a `ToolInvocationError` and re-raises every other exception. `ToolInvocationError.message` is filled from `TOOL_INVOCATION_ERROR_TEMPLATE`, which includes the tool name, the kwargs, the error text, and the sentence `Please fix the error and try again.` A handled error becomes a `ToolMessage` with `status="error"`. `GraphBubbleUp` and an invalid resume value are re-raised before that branch. Sources: [`templates`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L116-L129), [`ToolInvocationError.message`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L381-L388), [`default handler`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L391-L399), [`parameter default`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L751-L761), [`handled versus re-raised`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L995-L1029).

The default callable is annotated as taking `Exception`, so `_infer_handled_types` treats `Exception` as the handled type and then calls the callable. The callable itself re-raises anything that is not a `ToolInvocationError`. Sources: [`_infer_handled_types`](https://github.com/langchain-ai/langgraph/blob/a4d4187e82cdb0a73d68c76d70d655dd73a6db0b/libs/prebuilt/langgraph/prebuilt/tool_node.py#L500-L502).

Structured output is off unless `response_format` is set on `create_agent`, or `response_format` is set on `create_react_agent`. Both parameters default to `None`, as cited above.

## CrewAI 1.15.39

`Agent.use_system_prompt` defaults to `True`. `system_template`, `prompt_template`, and `response_template` default to `None`, so the English i18n slices are used. `Prompts.task_execution` starts from the `role_playing` slice. When the agent has tools and native tool calling is off, it appends the `tools` slice. Native tool calling selects the `native_task` slice for the user turn. Whether native calling is on depends on `_supports_native_tool_calling(raw_tools)` at prompt-build time. Sources: [`prompt fields`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agent/core.py#L285-L311), [`prompt assembly`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/utilities/prompts.py#L93-L131), [`native selection`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agent/core.py#L1309-L1315).

The `role_playing` slice is `You are {role}. {backstory}\nYour personal goal is: {goal}`. The `tools` slice describes Thought, Action, Action Input, and Observation. The `native_task` slice is `Current Task: {input}`. None of those three slices states what to do when a tool throws. Failure strings live under `errors`, including `tool_usage_exception`, and are formatted later as an error observation. Sources: [`en.json` slices](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/translations/en.json#L11-L16), [`errors.tool_usage_exception`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/translations/en.json#L50-L55).

On the text-action path, `ToolUsage` sets `_max_parsing_attempts` to 3, or 2 when the function-calling model is in `OPENAI_BIGGER_MODELS`. A tool exception increments the attempt count. While attempts remain, it calls `ause` again. After the cap, it returns a `ToolUsageError` string that includes `errors.tool_usage_exception` and the `format` slice. Sources: [`attempt cap`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/tools/tool_usage.py#L109-L134), [`exception branch`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/tools/tool_usage.py#L451-L499).

On the native tool-call path, an exception is caught and the tool message content is set to `Error executing tool: {e}`. That function does not call the tool again. `handle_tool_failure` then applies the resolved policy. `tool_failure_policy` defaults to `None` on the agent and on the task. `None` inherits, and the resolver falls through to `ToolFailurePolicy.WARN`. `WARN` records the failure, emits `ToolFailureDetectedEvent`, and returns. `RAISE` raises `ToolExecutionFailedError`. Sources: [`native except`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/utilities/agent_utils.py#L1685-L1704), [`native tool message`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/utilities/agent_utils.py#L1752-L1769), [`agent policy field`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agents/agent_builder/base_agent.py#L288-L296), [`task policy field`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/task.py#L293-L299), [`resolver`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/tools/tool_failure.py#L180-L211), [`WARN and RAISE`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/tools/tool_failure.py#L60-L71), [`handle_tool_failure`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/tools/tool_failure.py#L345-L387).

`Agent.max_retry_limit` defaults to 2. `_check_execution_error` re-raises passthrough exceptions and exceptions whose module starts with `litellm`. Other exceptions increment `_times_executed` and re-raise once the count exceeds `max_retry_limit`. Otherwise `_handle_execution_error` calls `execute_task` again. This retry wraps task execution. Sources: [`max_retry_limit`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agent/core.py#L325-L328), [`_check_execution_error`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agent/core.py#L908-L934), [`_handle_execution_error`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/agent/core.py#L936-L955).

`Task.output_json`, `output_pydantic`, and `response_model` default to `None`. `guardrail` and `guardrails` default to `None`. `guardrail_max_retries` defaults to 3 and applies when a guardrail is set. The `errors.validation_error` slice is the text used after a guardrail failure. Sources: [`output fields`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/task.py#L185-L214), [`guardrails`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/task.py#L262-L290), [`validation_error`](https://github.com/crewAIInc/crewAI/blob/adb4aba6bb72914ba56a1aa414bb768fbae4ebf4/lib/crewai/src/crewai/translations/en.json#L55).

## Pydantic AI 2.66.0

`Agent` defaults `instructions` to `None` and `system_prompt` to `()`. The constructor stores only the instructions the caller passed. The default agent has no system-prompt text about a failed tool. `output_type` defaults to `str`, and the docstring says that type is used to validate model output. `retries` defaults to `None`. `_normalize_agent_retries` fills a missing key with `default=1`, and the constructor assigns that result to `_max_tool_retries` and `_max_output_retries`. Sources: [`constructor defaults`](https://github.com/pydantic/pydantic-ai/blob/7d1d3f0191fd5d500b02e58dee2bf6d7adc1b967/pydantic_ai_slim/pydantic_ai/agent/__init__.py#L672-L683), [`output_type and retries docstring`](https://github.com/pydantic/pydantic-ai/blob/7d1d3f0191fd5d500b02e58dee2bf6d7adc1b967/pydantic_ai_slim/pydantic_ai/agent/__init__.py#L699-L724), [`retry normalization`](https://github.com/pydantic/pydantic-ai/blob/7d1d3f0191fd5d500b02e58dee2bf6d7adc1b967/pydantic_ai_slim/pydantic_ai/agent/__init__.py#L487-L493), [`assigned budgets and schema`](https://github.com/pydantic/pydantic-ai/blob/7d1d3f0191fd5d500b02e58dee2bf6d7adc1b967/pydantic_ai_slim/pydantic_ai/agent/__init__.py#L801-L826).

`_raw_execute` turns `ToolFailed` into a failed tool return and `ModelRetry` into a retry tool return after `_check_max_retries`. A `ValidationError` or `ModelRetry` raised from a hook is wrapped with `_wrap_error_as_retry` after `_check_max_retries`. The retry content is a `ToolReturnPart`: structured error details for a `ValidationError`, and `error.message` for a `ModelRetry`. When the retry count reaches the budget, `_check_max_retries` raises `UnexpectedModelBehavior`. A plain `Exception` from the tool body is passed to `on_tool_execute_error`. The base capability implementation re-raises that error. `CombinedCapability` also re-raises if no capability returns a replacement value. Sources: [`_raw_execute`](https://github.com/pydantic/pydantic-ai/blob/7d1d3f0191fd5d500b02e58dee2bf6d7adc1b967/pydantic_ai_slim/pydantic_ai/tool_manager.py#L1325-L1342), [`hook wrap`](https://github.com/pydantic/pydantic-ai/blob/7d1d3f0191fd5d500b02e58dee2bf6d7adc1b967/pydantic_ai_slim/pydantic_ai/tool_manager.py#L756-L785), [`_check_max_retries`](https://github.com/pydantic/pydantic-ai/blob/7d1d3f0191fd5d500b02e58dee2bf6d7adc1b967/pydantic_ai_slim/pydantic_ai/tool_manager.py#L519-L533), [`retry content`](https://github.com/pydantic/pydantic-ai/blob/7d1d3f0191fd5d500b02e58dee2bf6d7adc1b967/pydantic_ai_slim/pydantic_ai/_output.py#L126-L155), [`default on_tool_execute_error`](https://github.com/pydantic/pydantic-ai/blob/7d1d3f0191fd5d500b02e58dee2bf6d7adc1b967/pydantic_ai_slim/pydantic_ai/capabilities/abstract.py#L1388-L1425), [`combined handler`](https://github.com/pydantic/pydantic-ai/blob/7d1d3f0191fd5d500b02e58dee2bf6d7adc1b967/pydantic_ai_slim/pydantic_ai/capabilities/combined.py#L932-L952).

Output validation is the schema built from `output_type`. The default type is `str`. A caller-supplied type uses the output retry budget, which defaults to 1.

## AG2 1.3.0

A bare `Agent(name, config)` is documented as having zero harness middleware and running a plain LLM loop. `prompt` defaults to `()`. `response_schema` defaults to `None`, and `ResponseSchema.ensure_schema(None)` returns `None`. `system_prompt` returns the static fragments the caller registered. The default agent has no system-prompt text about a failed tool, and it has no response schema. Feature prompts such as A2UI are separate from this constructor. Sources: [`class docstring and defaults`](https://github.com/ag2ai/ag2/blob/1229064a23a1e39a4c3c089bb4643a637117c8a9/ag2/agent.py#L774-L795), [`constructor defaults`](https://github.com/ag2ai/ag2/blob/1229064a23a1e39a4c3c089bb4643a637117c8a9/ag2/agent.py#L878-L908), [`system_prompt`](https://github.com/ag2ai/ag2/blob/1229064a23a1e39a4c3c089bb4643a637117c8a9/ag2/agent.py#L964-L968), [`ensure_schema`](https://github.com/ag2ai/ag2/blob/1229064a23a1e39a4c3c089bb4643a637117c8a9/ag2/response/schema.py#L94-L103).

`_execute_call` lets `HumanInputError` propagate. Any other `Exception` returns `ToolErrorEvent.from_call`. That event stores `traceback.format_exception` text as a `ToolResult`. A string argument to `ToolResult` becomes a `TextInput`. The executor appends the `ToolErrorEvent` to the batch and publishes a `ToolResultsEvent`, except when another tool in the same batch has `result.final`, which ends the turn. `_execute_turn` sends tool calls and waits for the next `ModelResponse`. `MultiStepAgent.max_steps` defaults to 20. `final_answer_checks` defaults to `None` and is stored as `[]`. The step loop re-raises `AgentGenerationError`. It stores any other `AgentError` on `action_step.error` and continues. `execute_tool_call` turns a tool-body exception into `AgentToolExecutionError`, whose message includes the exception and `Please try again or use another tool`. `AgentToolExecutionError` subclasses `AgentError`. For `CodeAgent`, `LocalPythonExecutor` evaluates the code, and `evaluate_python_code` raises `InterpreterError` from a generic `Exception` inside the snippet, with the exception type and message in the text. `CodeAgent` catches that and raises `AgentExecutionError`, which also subclasses `AgentError`.
